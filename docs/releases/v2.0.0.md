# v2.0.0 — first tagged release

**Pipeline Orchestrator** is a declarative multi-agent pipeline engine for the pi
coding-agent ecosystem. Define a multi-phase workflow as a JSON state machine; the engine
discovers entities, runs sub-agents in parallel, retries failures, pauses at LLM decision
points, and resumes after a restart.

This is the first tagged release. The 2.x engine targets
[omp](https://github.com/can1357/oh-my-pi) (`@oh-my-pi/pi-coding-agent`), the actively
developed fork of Pi, and runs sub-agents in-process through its agent SDK. Legacy
`pi.extensions` manifests and `.pi/` paths are still honored.

## Highlights

- **Route-table state machines** — AND-combined conditions (`exitCode`, `validatePassed`,
  `outputContains`, `outputRegex` + numeric compare, `fileExists`, `fileMinSize`,
  `fileMaxSize`, `bash`, fallback) with `iter` loops, `done`, and `__LLM__` decision
  points.
- **Parallel entities** — `concurrency: N` caps entities in flight; a paused `__LLM__`
  entity releases its slot so the others keep running.
- **Resumable by default** — state is persisted to agent session entries (plus a
  `memory` fallback) and incomplete runs resume on restart.
- **Structured phase output** — sub-agents call `yield` with
  `{verdict, summary, keyFindings}`; later phases consume
  `{lastPhaseSummary.verdict}` / `{lastPhaseSummary.keyFindings}`.
- **Operational tooling** — `/pipeline validate`, `/pipeline graph` (Mermaid),
  `/pipeline logs`, per-entity `.log` + `.trace.jsonl`, dual logging.
- **Compatibility** — skill → project → user agent discovery, `.omp` paths preferred and
  legacy `.pi/` paths still read; `$PI_CODING_AGENT_DIR` honored.

## Install

```bash
git clone https://github.com/varsian/pi-pipeline-orchestrator
cd pi-pipeline-orchestrator
mkdir -p ~/.omp/agent/extensions
cp -r plugins/pipeline-orchestrator ~/.omp/agent/extensions/pipeline-orchestrator
```

Requires **Node.js ≥ 22** and omp (oh-my-pi) with the in-process agent SDK.

## Breaking changes vs. the v1 pi-era engine (untagged)

- Runtime is omp (oh-my-pi), not upstream Pi; the engine imports
  `@oh-my-pi/pi-coding-agent` and uses `createAgentSession` instead of spawning `pi`.
- `conditional` transitions are rejected by the validator — use routes +
  `outputContains` or `"type": "llm"`.
- Node.js 22+ is required (`Promise.withResolvers`).

## Fixes

- Extension could fail to parse: invalid string literal in `generateGraph` labels.
- Agent phases could throw `ReferenceError: taskPrompt is not defined`.
- Legacy conditional decisions could throw `ReferenceError: nextPhase is not defined`.
- The validator rejected all pipelines containing loops; it now only rejects cycles
  without any `iter` edge.

## Known limitations

- Single-maintainer, early-stage project; the pipeline JSON schema may still change.
- No npm package: install by copying the plugin directory.
- Upstream Pi is not supported out of the box (SDK import swap needed).
- `bash` validation, hooks, and `skipIf` execute with the current user's permissions —
  treat pipeline definitions as executable code (see [SECURITY.md](../../SECURITY.md)).
